    Catan: how it plugs in

    Catan support is a ruleset plug-in in src/logic/catan/. The engine did not change shape. It got one optional field (IGameResult.scores) and three opt-in IRuleset hooks. Each hook's default keeps Commander and 1v1 MTG on their old code path, and tests/test_golden.py checks this. Rules reference: https://catanevents.com/hosts/tournament-rules/ (rule numbers below). Authoritative contracts: docs/tournament-log-spec.md (CatanRuleset, ScoringCatan, PairingCatanPrelim, PairingCatanSerpentine, format 1.3).

    Event flow

    Structure by player count (rule 1.1.5, recommended_structure(n), which reads the bands from src/logic/catan/CatanRuleset.setup.yaml). The config stays explicit; CatanRuleset.warn_structure logs once at game 1 if it differs or if there are fewer than 12 players.

    Players Swiss games Large-event step Playoffs Config
    12–28 3 — Final (top 4) n_rounds=3, top_cut=4
    29–79 3 — Semis (top 16) → Final n_rounds=3, top_cut=16
    80+ 4 0-win players out before game 4 Semis (top 16) → Final n_rounds=4, top_cut=16, round 4 ruleset_params.eliminate_below_wins=1

  J --> K
  I -- "4" --> K["Final: advancing_players → PairingTopCut TOP_4"]
  K --> L["Final standings: get_standings → CatanRuleset.playoff_standings<br/>1-4 by final place; 5-16 by semi place"]
    • Prelim plan (PairingCatanPrelim.plan, _schedule): hill climbing over all remaining preliminary games. Repeat opponents and repeat 3-player seats cost 100× more than repeat play-order positions (rule 1.1.6 priority). The seed is sha256(tour uid | plan start round | sorted field), so nothing extra is saved. If an earlier round's actual seating differs from the plan, the plan restarts after it, with the real seating as history.
    • Game 4 (PairingCatanSerpentine): pods sorted 3-seat first, then ranks snaked across them, seat order = rank order (rule 1.1.7; the 45-player example is a test).
    • Semis/final: no Catan pairing code. Commander's PairingTopCut, looked up by name, already gives the rule 1.1.10 seating.
    • Playoff standings (playoff_standings): until every table of the round has reported, the previous round's standings stand. Then that round's players are grouped by finishing place at their table, with ties broken by the 1.4.2 chain over preliminary and playoff games. Everyone else keeps the previous order.

    Data

    flowchart LR
  R["Report (one game per table)<br/>IGameResult(winners={P11},<br/>scores=((P8,9),(P10,9),(P11,10)))"] --> P["Per game (scoring.py)<br/>finishing_places: P11=1, P8=2, P10=2<br/>vp_share: 3-player table adds dummy<br/>mean 9.33 → 9 (half-up); total 37"]
  P --> S["Per player: catan_stats → CatanStats<br/>vp = Σ min(VP, victory_points)<br/>vp_pct = Σ share (Fraction)<br/>second, third = place counts"]
  S --> K["ScoringCatan.standings_keys (desc)<br/>(wins·win_points, vp, vp_pct,<br/>second, third, -uid)"]
  R --> L["Log 1.3: pods[].games[] =<br/>{winners:[uid], scores:[[uid, vp], …]}"]
    • Valid report (CatanRuleset.validate_report): exactly one game and one winner; VP for exactly the seated players; winner ≥ victory_points (default 10); everyone else below it. report_from_winners always refuses, so a Catan win needs VP.
    • Places: by VP; tied players share the better place (two players on 9 VP are both 2nd).
    • VP% (rule 1.4.3): own VP / table total, summed over games as exact Fractions. A 3-player table adds a dummy fourth score, the mean rounded half up (dummy_score, not round()). The column shows the share (0.2703), not a percentage.
    • Byes: off by default. A forced bye scores bye_points (default 0) and adds no VP. With byes off, pairing a field that tables of 3-4 cannot seat (1, 2 or 5 players) raises a ValueError (Round._require_seats); a table of 5 seated by hand in Manual Entry still pairs.
    • Lot: the core's stable UID order.
    • Log: only raw VP is stored (games[].scores, sorted by UID, omitted when unset). Places, VP%, standings and the preliminary plan are recomputed on load. Every file now says "format_version": "1.3". players[].decklist is written only when it is set.

    Adding another game the same way

    1. Freeze first. Before you touch shared code, make sure tests/test_golden.py covers the behaviour you could break, and keep it green.
    2. Ruleset. src/logic/<game>/rules.py: an IRuleset (validate_report, match_winners, random_report, PLAYOFFS, pod sizes, DEFAULT_ALLOW_BYE) plus a TournamentConfiguration subclass named by CONFIG_CLASS, each with a .params.yaml sidecar. Keep IS_COMPLETE = False until the game works end to end.
    3. Scoring and pairing on the common bases, with RULESETS = ("<Game>Ruleset",). Reuse another game's logic only by name (for example in PLAYOFFS), never by import, and add the pairs to tests/test_logic_layout.py.
    4. Seams, not rewrites. If the core cannot express a rule, add an opt-in hook or optional field whose default is the old path. Per-game result data goes in IGameResult.scores.
    5. Switch on. Rule-example tests, an end-to-end run, the spec section in docs/tournament-log-spec.md, then IS_COMPLETE = True. Add a GUI dialog only if the existing win/score dialogs cannot capture a result.
